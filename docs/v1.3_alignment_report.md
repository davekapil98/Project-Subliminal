## Reconciliation performed

- Replaced the v1.2 master document with v1.3 and made it authoritative in the
  active documentation.
- Removed paid GB100 rental, mandatory custom Isaac generation and mandatory
  NVFP4 from the active baseline. Quantization is an optional later deployment
  evaluation behind accuracy gates.
- Corrected the model budgets and fixed production bus target to 512D without
  pretending the tiny Stage 0 fixtures are full-size models.
- Reframed Stage 1 around public simulated and real multi-embodiment data,
  followed later by public and self-collected SO-101 specialization.
- Added immutable raw-source tiers, cleaned/normalized/model-shard boundaries,
  source registry and cleaning-profile locations, and explicit sim/real/own
  provenance.
- Strengthened canonical episode and manifest validation so action semantics,
  units, frames, embodiment, revision, license, redistribution terms and
  checksums cannot be implicit.
- Extended the gate for camera masking, audio semantics, 512D integration, all
  eight checkpoints and the exact v1.3 parameter budget.
- Preserved `.env`, credentials, raw/cleaned/normalized data, training shards,
  recordings, checkpoints and model binaries as Git-prohibited content while
  allowing only small reviewed manifest/split metadata.

## Why Stage 1 is not yet complete

Scaffolding and schemas establish readiness, not data admission. Stage 1 begins
with evidence about real public sources. At present the repository contains no
pinned source revision with reviewed license/redistribution terms and checksum,
no decoded source subset, and no source-specific adapter output. Claiming Stage
1 progress beyond preparation would therefore be misleading.

## Next stage: Stage 1.1 source qualification

Work one Priority-A public SO-101 source end to end before any bulk download:

1. Verify the official dataset card, immutable revision, direct source URL,
   license, redistribution terms, modalities, embodiment, action semantics,
   units/frames and disk estimate.
2. Add a `planned` registry record, download only metadata and a small episode
   subset into the ignored `data/raw/public_real/` or `public_sim/` tier, then
   record its checksum.
3. Decode representative episodes and test timestamps, camera streams, robot
   state, native actions, task text, missingness and corruption behavior.
4. Implement the first source-specific adapter without discarding native
   actions or inventing cross-embodiment equivalence.
5. Produce a reproducible canonical sample plus manifest and integrity tests;
   promote the source to `validated` only after those checks pass.
