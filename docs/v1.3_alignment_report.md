## Stage 1.1 completed evidence

The first Priority-A source is Project IRA SO-101 at immutable Hugging Face
revision `bf6f568e9ec218fff838fb266e161724ec4f7e2c`. The CC-BY-SA-4.0
license, redistribution obligations, schema, exact source objects, native action
semantics, source-native units and limitations are pinned.

The qualification verifies all 844,208 numeric rows across 930 episodes and 93
prompts, plus 435,441,545 bytes of exact metadata, trajectory and episode-0
dual-camera media. Both H.264 streams decode at 30 fps, six real RGB frames are
represented in a canonical two-transition sample, and exact prompt groups are
kept wholly within a family-stratified 750/90/90 episode
train/validation/test split. See
`docs/stage1_1_project_ira_report.md` and the machine-readable qualification
record under `data/manifests/`.

## Why Stage 1 is not yet complete

Source validation is not training admission and one source is not the full
Priority-A inventory. Project IRA has no published task-success labels, quality
labels, camera calibration or task-space frame. Native actions therefore remain
absolute source-calibrated SO-101 positions, and no task-space conversion is
allowed. The later public-data gate must also prove held-out target-model
improvement without leakage or unacceptable forgetting.

## Next stage: Stage 1.2 additional Priority-A qualification

Qualify the next complementary direct-embodiment source, beginning with the
current authoritative ArmnetBench SO-101 card, using the same subset-first gate:

1. Reverify the current card, license, immutable revision, source layout and
   full/subset storage footprint.
2. Pin source objects and decode a small real episode subset without committing
   raw or cleaned data.
3. Implement its adapter, preserve success/failure/suboptimal labels, and test
   action units, timestamps, camera alignment and corruption behavior.
4. Freeze leakage-resistant splits and produce a canonical sample plus
   qualification record.
5. Compare overlap and complementary value against Project IRA before any bulk
   download or mixture decision.

Bulk acquisition, mixing and specialist training remain blocked until the
selected Priority-A sources are repeatably qualified. Full Stage 1 exits only
after those sources are pinned, validated, canonicalized and reproducibly
shardable for their target modules.
